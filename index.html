The math

Cable lengths are 3D Pythagoras from each tower top Ti to the commanded camera position P; payout rates are the motion projected onto each cable:

Li = |P − Ti|   ·   dLi/dt = ((P − Ti) · v) / Li

Motion profile — speed is governed so the rig can always brake to the target at accel limit a:

|v| ≤ min( vmax, √(2 · a · dremaining) )

Gondola dynamics — the rendered gondola is a damped spring chasing the commanded point (softer horizontally, stiffer vertically), so it lags under acceleration and bobs on arrival:

ẍ = ω²(Pcmd − x) − 2ζω·ẋ

Reels — payout speed maps to drum RPM through the effective radius, which grows as cable layers wind on:

reff = rcore + layer · dcable   ·   RPM = 60 · |dL/dt| / (2π · reff)

Drum: 0.35 yd core radius, 8 mm cable, 38 wraps per layer, 300 yd capacity per winch. Same cable, same motor speed, different layer → different line speed. That’s why real winches encoder the cable, not just the motor.

Rigidity — cables only pull, so a 4-cable suspended CDPR relies on gravity as the fifth “cable” and its stiffness scales with tension. The slider stands in for tension + control gain. Real rigidity upgrades: more cables pulling against each other (NIST RoboCrane uses 6; 8-cable machines constrain all six degrees of freedom), heavier platform, higher preload, and input shaping so commands never excite the swing modes.
